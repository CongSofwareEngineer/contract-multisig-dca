# Swap V3
- **Date**: 2026-10-09
- **Feature**: swap-v3 (→ docs/instruction/swap-v3.md)
- **Type**: Fixed
- **Files**: `src/vault/DCAVaultStorage.sol`, `src/vault/DCAVaultRoles.sol`, `src/vault/DCAVaultSwap.sol`, `src/vault/DCAVaultMorpho.sol`, `test/DCAVault.security.t.sol`, `DCA_VAULT_SPEC.md`, `CLAUDE.md`, `docs/instruction/swap-v3.md`, `docs/instruction/swap-v4.md`, `docs/instruction/morpho-integration.md`, `docs/instruction/security-safety.md`, `docs/instruction/deployment.md`
- **What**:
  - **Pool whitelist key (`allowedPool`)**: entries are now keyed by `_poolId = keccak256(stableEpoch, token, _tokenEpoch[token], fee, tickSpacing)` (`mapping(bytes32 => bool)`) instead of `[stable][token][fee][tickSpacing]`. New state: `uint64 public stableEpoch` (bumped by `ChangeStableToken`), `mapping(address => uint256) internal _tokenEpoch` (bumped by `RemoveToken`).
  - **ChangeStableToken**: kills every pool entry for good — switching back to a previous stable (USDC → X → USDC) no longer revives the old USDC entries.
  - **RemoveToken**: kills that token's pool entries for good — `AddToken` again opens no pool until signers `SetAllowedPool` again. Other tokens' entries are untouched.
  - `SetAllowedPool` remove on a dead entry → `NotFound`; re-adding it is not `Duplicate`. V3 / V4 swaps check the same id. Event `PoolAllowed` unchanged; off-chain rebuild must drop entries followed by `StableTokenChanged` / `TokenAllowed(token, false)`.
  - Contract size 23,942 B → 24,120 B (456 B under EIP-170).
- **Tests**: added `test_Security_ChangeStableTokenBackDoesNotReviveOldPools`, `test_Security_RemoveTokenThenAddTokenDoesNotRevivePools`. `forge test` (incl. Base mainnet fork): 221 passed, 0 failed.
- **Why**:
  - 2026-10-09 security review: entries were only hidden, not dropped. A stale entry revived by A → B → A or RemoveToken → AddToken may point at a pool that has lost its liquidity since it was vetted, which a leaked operator key could manipulate cheaply (spec §16.1). Owner chose epoch keys.
