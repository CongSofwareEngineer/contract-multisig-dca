# Deployment
- **Date**: 2026-10-08
- **Feature**: deployment (→ docs/instruction/deployment.md)
- **Type**: Added, Changed
- **Files**: `script/Deploy.s.sol`, `.env.example`, `.gitignore`, `foundry.toml`, `src/DCAVault.sol`, `src/interfaces/IV4Router.sol`, `src/vault/DCAVaultSwapV3.sol`, `src/vault/DCAVaultSwapV4.sol`, `test/DCAVault.fork.t.sol`, `src/vault/*.sol`, `test/DCAVault.t.sol`, `test/DCAVault.security.t.sol`, `test/helpers/VaultTestBase.sol`, `src/vault/DCAVaultRoles.sol`, `DCA_VAULT_SPEC.md`, `CLAUDE.md`
- **What**:
  - **Project setup**: Foundry 1.8.5, solc 0.8.24, OpenZeppelin v5.1.0, forge-std.
  - **Deploy script**: env-driven config, chainId + code + Morpho-asset pre-flight, prints config.
  - **Address verification**: all spec §3 addresses checked on-chain; pool liquidity per fee tier recorded. Steakhouse USDC identified as a Morpho Vault V2.
  - **Stable / tradable tokens**: constructor's first arg is now `_stableToken`; `tokens[]` holds tradable tokens only (stable inside → `StableNotTradable`; `address(0)` = native ETH allowed). `Deploy.s.sol` reads `STABLE_TOKEN` and `TOKENS` (comma list; `.env.example`: WETH, cbBTC) instead of `USDC` / `WETH` / `CBBTC`; pre-flight checks code for every non-zero token, `STABLE_TOKEN ∉ TOKENS`, Morpho `asset() == STABLE_TOKEN`. Runtime size 24,238 B (338 B under the 24,576 B EIP-170 limit).
  - **Constructor / deploy script**: last constructor arg is `PoolConfig[] pools` (pool whitelist, one `(token, fee, tickSpacing)` per pool, 0 = V3). `Deploy.s.sol` reads parallel env lists `POOL_TOKENS` / `POOL_FEES` / `POOL_TICK_SPACINGS` (equal length required) and `UNI_V3_FACTORY`; pre-flight requires every V3 entry to exist (`getPool != 0`) and prints each pool. `.env.example` default = the 5 pools verified on Base: V3 USDC/WETH 500, V3 USDC/cbBTC 500, V4 USDC/WETH 500/10 + 3000/60, V4 USDC/cbBTC 500/10. No on-chain pool list (kept the contract under the size limit).
  - **Source layout**: `DCAVault` split into abstract modules under `src/vault/` (`DCAVaultStorage` → `Roles` → `Morpho` → `Swap` / `Proposals`), compiled into one immutable contract. Swap code split into `DCAVaultSwap` (shared `_checkSwap` / `_settleSwap`) → `DCAVaultSwapV3` and `DCAVaultSwapV4`; `DCAVault is DCAVaultSwapV3, DCAVaultSwapV4, DCAVaultProposals`. Storage layout and function / event / error selectors identical to the single-file version; tests reference errors, events and `ProposalType` via `DCAVaultStorage`. See docs/instruction/deployment.md §5.
- **Tests**: dry-run of Deploy.s.sol against Base (simulation reached deploy; no broadcast). 125 passed, 0 failed (88 unit, 27 security, 10 fork on Base mainnet). Without BASE_RPC_URL the fork suite is skipped. After the source split: `forge test` 115 passed, 1 skipped (fork suite, no BASE_RPC_URL locally); ABI + storage layout diffed equal before/after. After the V4 / tick-spacing change: `forge test` (incl. Base mainnet fork) 174 passed, 0 failed. After the stable / tradable split + native ETH: `forge test` (incl. Base mainnet fork): 203 passed, 0 failed (148 unit, 38 security, 17 fork). Deploy script dry-run against Base with dummy signers: pre-flight (incl. V3 pool existence) passed and the in-script deploy simulated; on-chain simulation stopped only because the dummy deployer has no ETH. No broadcast.
- **Why**:
  - Spec §11–§13 Phase 1 step 8.
  - Pools in the constructor: so V3 / V4 swaps work right after deploy without a proposal; pool whitelist per `(token, fee, tickSpacing)` from the 2026-10-08 security review (see swap-v3).
  - V3 / V4 split: owner request (2026-10-08) — one file per Uniswap version is easier to read and review.
  - Stable / tradable split + native ETH: owner request (2026-10-08).
  - Source layout: the 840-line `DCAVault.sol` was hard to read; one file per concern makes review / audit easier.
