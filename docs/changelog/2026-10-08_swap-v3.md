# Swap V3
- **Date**: 2026-10-08
- **Feature**: swap-v3 (→ docs/instruction/swap-v3.md)
- **Type**: Added, Changed, Fixed
- **Files**: `src/vault/DCAVaultSwap.sol`, `src/vault/DCAVaultSwapV3.sol`, `src/vault/DCAVaultSwapV4.sol`, `src/vault/DCAVaultStorage.sol`, `src/vault/DCAVaultRoles.sol`, `src/vault/DCAVaultProposals.sol`, `src/DCAVault.sol`, `src/interfaces/ISwapRouter02.sol`, `test/helpers/VaultTestBase.sol`, `test/DCAVault.security.t.sol`, `test/DCAVault.t.sol`, `test/DCAVault.fork.t.sol`, `test/mocks/MockSwapRouter.sol`
- **What**:
  - **swapExactInputV3**: whitelisted tokens + fee, deadline checked in-contract, atomic approve, recipient = vault, output measured by balance delta, sell → auto-deposit proceeds to Morpho. **One side must be `stableToken`** (`PairNotAllowed` otherwise), the other must be in `allowedToken` (`TokenNotAllowed`): only cbBTC/USDC and WETH/USDC pools run, no WETH ↔ cbBTC. Native ETH (`address(0)`) is rejected on V3 (`NativeNotSupported`).
  - **withdrawAndSwapV3**: `withdrawAndSwapV3(tokenOut, fee, stableAmount, amountOutMinimum, deadline)` — exact Morpho withdraw + swap in one tx; `tokenOut` must be a whitelisted tradable token (not the stable, not native ETH) and `(tokenOut, fee, V3_POOL)` a listed pool — all checked before touching Morpho.
  - **Pool whitelist (`allowedPool`)**, shared by V3 and V4: one entry = one pool `(token, fee, tickSpacing)` vs the stable, `tickSpacing = 0` (`V3_POOL`) = V3 pool, `>= 1` = hookless V4 pool. Seeded by constructor `PoolConfig[] _pools`, changed via `SetAllowedPool` proposal; event `PoolAllowed`, error `PoolNotAllowed`; fee `1..1_000_000`, spacing `0..32767`, no stable-side entry, no V3 entry for native ETH. No on-chain list (size limit) — rebuild from events. Replaces the independent `allowedFee` / `allowedTickSpacing` lists (`FeeNotAllowed`, `FeeAllowed`, `SetAllowedFee` gone). V3 now rejects native ETH before the pool check.
  - **Shared swap helpers**: checks moved to `_checkSwap`, balance-delta / `Swapped` / sell-to-Morpho moved to `_settleSwap`, both reused by `swapExactInputV4`; V3 behavior unchanged. the pool whitelist also gates V4 swaps.
  - **Router address**: `uniV3Router` is now state, changeable only via a threshold `ChangeUniV3Router` proposal; `_swapV3` reads the current value.
- **Tests**: every revert path, buy/sell; `test_Revert_SwapExactInputV3_NonUsdcPair`, `testFuzz_Security_SwapNeedsUsdcSide`; fork: USDC→WETH (500, QuoterV2 minOut), USDC→cbBTC (500), WETH→cbBTC rejected (`test_Fork_Revert_SwapExactInputV3_WethToCbbtc`), slippage revert; `test_Proposal_ChangeUniV3RouterSwapsUseNewRouter`, `test_Security_OldRouterHasNoPowerAfterChange`; `test_Revert_SwapExactInputV3_Native`, `test_Revert_WithdrawAndSwapV3_Native`, `test_Revert_WithdrawAndSwapV3_TokenOutStable`, stable → stable now `TokenNotAllowed`. `forge test` (incl. Base mainnet fork): 203 passed, 0 failed (148 unit, 38 security, 17 fork). Pool whitelist: `test_Revert_SwapExactInputV3_PoolNotAllowed`, `test_Revert_SwapExactInputV3_OnlyV4EntryListed`, `test_Revert_WithdrawAndSwapV3_PoolNotAllowedBeforeMorpho`, `test_Proposal_SetAllowedPool`, `test_Proposal_RemovePoolBlocksSwap`, `test_Revert_Proposal_SetAllowedPool*`, `test_Revert_Constructor_Pool*` / `DuplicatePool`, `test_Constructor_SameFeeDifferentPoolsAreDistinct`, security `testFuzz_Security_UnlistedPoolAlwaysRejected`, fork `test_Fork_Revert_SwapExactInputV4_UnlistedPoolCombo`.
- **Why**:
  - Initial implementation of DCA_VAULT_SPEC.md §5.2 and §7. Balance-delta check added so a misbehaving router's return value can't be trusted blindly.
  - Changeable router: owner request (2026-10-08 security review) — Uniswap addresses must be replaceable without redeploying.
  - Shared helpers: V4 swap implemented with the same rules (owner request, 2026-10-08) — one code path for the checks avoids V3/V4 drift.
  - USDC-side rule: owner decision — only the BTC/USDC and ETH/USDC pools may be used; reduces the pools a compromised operator can route value through.
  - Stable / tradable split: owner request (2026-10-08) — one stable compared by address, tradable tokens kept in their own list.
  - Pool whitelist: 2026-10-08 security review — with independent fee / tick-spacing lists a stolen operator key could route the whole vault into a fresh, attacker-seeded pool (e.g. V4 USDC/WETH 500/60, permissionless to create) with `minOut = 1` and drain it without capital. Owner chose one entry per pool `(token, fee, tickSpacing)` — readable numbers, no PoolId lookup.
