# Swap V3
- **Date**: 2026-10-08
- **Feature**: swap-v3 (→ docs/instruction/swap-v3.md)
- **Type**: Added, Changed
- **Files**: `src/vault/DCAVaultSwap.sol`, `src/vault/DCAVaultSwapV3.sol`, `src/vault/DCAVaultSwapV4.sol`, `src/vault/DCAVaultStorage.sol`, `src/interfaces/ISwapRouter02.sol`, `test/DCAVault.security.t.sol`, `test/DCAVault.t.sol`, `test/DCAVault.fork.t.sol`, `test/mocks/MockSwapRouter.sol`
- **What**:
  - **swapExactInputV3**: whitelisted tokens + fee, deadline checked in-contract, atomic approve, recipient = vault, output measured by balance delta, sell → auto-deposit proceeds to Morpho. **One side must be USDC** (`PairNotAllowed` otherwise): only cbBTC/USDC and WETH/USDC pools run, no WETH ↔ cbBTC.
  - **withdrawAndSwapV3**: exact Morpho withdraw + swap in one tx.
  - **allowedFee**: constructor list + SetAllowedFee proposal.
  - **Shared swap helpers**: checks moved to `_checkSwap`, balance-delta / `Swapped` / sell-to-Morpho moved to `_settleSwap`, both reused by `swapExactInputV4`; V3 behavior unchanged. `allowedFee` also gates V4 swaps.
  - **Router address**: `uniV3Router` is now state, changeable only via a threshold `ChangeUniV3Router` proposal; `_swapV3` reads the current value.
- **Tests**: every revert path, buy/sell; `test_Revert_SwapExactInputV3_NonUsdcPair`, `testFuzz_Security_SwapNeedsUsdcSide`; fork: USDC→WETH (500, QuoterV2 minOut), USDC→cbBTC (500), WETH→cbBTC rejected (`test_Fork_Revert_SwapExactInputV3_WethToCbbtc`), slippage revert; `test_Proposal_ChangeUniV3RouterSwapsUseNewRouter`, `test_Security_OldRouterHasNoPowerAfterChange`. `forge test` (incl. Base mainnet fork): 174 passed, 0 failed (125 unit, 35 security, 14 fork).
- **Why**:
  - Initial implementation of DCA_VAULT_SPEC.md §5.2 and §7. Balance-delta check added so a misbehaving router's return value can't be trusted blindly.
  - Changeable router: owner request (2026-10-08 security review) — Uniswap addresses must be replaceable without redeploying.
  - Shared helpers: V4 swap implemented with the same rules (owner request, 2026-10-08) — one code path for the checks avoids V3/V4 drift.
  - USDC-side rule: owner decision — only the BTC/USDC and ETH/USDC pools may be used; reduces the pools a compromised operator can route value through.
